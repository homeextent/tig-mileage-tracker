# Developer Build, Release & Deployment Guide — TIG Corporate Mileage Tracker

Operational workflow for packaging `homeextent/tig-mileage-tracker` into a clean, WordPress-installable `.zip` archive and deploying updates to `theinnovativegroup.ca`.

---

## 1. Git & One-Command Production ZIP Build

Run these commands from `/media/jeremy/MEDIA/GITHUB/tig-mileage-tracker`:

```bash
# 1. Verify status (ensure no Timeline*.json, *.csv, or *.xlsx files are untracked/staged)
git status

# 2. Stage and commit completed milestone
git add -A
git commit -m "feat: release v3.1.0"
git push origin main

# 3. Build pristine WordPress-ready .zip (outputs ../tig-mileage-tracker.zip)
./build.sh
```

**Direct One-Liner (works on Linux, macOS, and Windows PowerShell/Git Bash without running `build.sh`):**

```bash
git archive --format=zip --prefix=tig-mileage-tracker/ --output=../tig-mileage-tracker.zip HEAD
```

> **Why `--prefix=tig-mileage-tracker/` matters:** WordPress requires the `.zip` to extract into a single `tig-mileage-tracker/` directory so **Upload Plugin > Replace current with uploaded** overwrites `/wp-content/plugins/tig-mileage-tracker/` cleanly without creating duplicate plugin folders. `.gitattributes` automatically excludes `.gitignore`, `.gitattributes`, `DEVELOPER.md`, and `build.sh` from the archive.

## 2. Pre-Flight Safety Verification Checklist

Run through these checks before building and uploading:

* [ ] **Single Bootstrap File:** Confirm `tig-mileage-tracker.php` is the only `.php` file in the plugin root (prevents duplicate function fatal errors).
* [ ] **Header Version:** Update `Version: X.Y.Z` in the `tig-mileage-tracker.php` plugin docblock.
* [ ] **Constant Version:** Update `define('TIG_MILEAGE_VERSION', 'X.Y.Z');` to match the header version.
* [ ] **Canonical Slug Preserved:** Confirm `add_menu_page()` still uses `'tig-mileage'` so existing admin bookmarks/tabs never break.
* [ ] **Changelog Updated:** Prepend itemized release notes for `## [X.Y.Z]` in `CHANGELOG.md`.
* [ ] **Bundled Geo-Cache Intact:** Verify `data/geo_cache.json` is present and valid JSON.
* [ ] **Clean Working Tree:** Confirm `git status` shows zero raw `Timeline.json`, QBO `.csv`, or `.xlsx` files before committing.

## 3. GitHub Release Protocol

1. Tag and push the release from `/media/jeremy/MEDIA/GITHUB/tig-mileage-tracker`:
   ```bash
   git tag -a v3.1.0 -m "Release v3.1.0"
   git push origin main --tags
   ```
2. Open `https://github.com/homeextent/tig-mileage-tracker/releases` and click **Draft a new release** (or edit the pushed tag).
3. Paste the latest entry from `CHANGELOG.md` into the **Description** field.
4. Drag and drop `../tig-mileage-tracker.zip` generated by `./build.sh`.
5. Click **Publish release**.

---

## 4. SiteGround WordPress Deployment (Zero Data Loss)

All user-configured project locations (`tig_mileage_locations`), odometer anchors (`tig_mileage_anchors`), and runtime reverse-geocoded coordinates (`tig_mileage_runtime_geocache`) are stored in MySQL `wp_options`, so replacing the plugin `.zip` preserves 100% of your configuration.

1. Log into `https://theinnovativegroup.ca/wp-admin/`.
2. Navigate to **Plugins > Add New > Upload Plugin**.
3. Choose `tig-mileage-tracker.zip` and click **Install Now**.
4. When WordPress displays *"Destination folder already exists"*, click **Replace current with uploaded**.
5. Clear caches so updated admin JavaScript loads immediately:
   * Click **Purge SG Cache** in the WordPress top admin bar (or **Speed Optimizer > Caching > Purge Cache**).
   * Hard-refresh the **TIG Mileage** admin tab (`Ctrl + Shift + R` or `Cmd + Shift + R`).
